# 架构说明

> 这份文档解释**为什么这样分层**，以及**改哪里不会出事**。
> 想知道每个文件干什么看 `STRUCTURE.md`；想接手开发看 `HANDOVER.md`。

## 一、分层与数据流

```
                       ┌──────────────────────────────────────────┐
   物理世界            │  Transport  串口/TCP/UDP/BLE/文件         │  core/transport.py
                       │  只搬字节，不认识协议                      │
                       └──────────────────┬───────────────────────┘
                                          │ bytes
                       ┌──────────────────▼───────────────────────┐
                       │  Codec  切帧：帧头/长度/帧尾               │  core/codec.py
                       │  处理粘包、半包、假同步                    │
                       └──────────────────┬───────────────────────┘
                                          │ 完整帧
                       ┌──────────────────▼───────────────────────┐
                       │  Driver  语义化：帧 → RadarFrame          │  drivers/*
                       │  只填它擅长的那一半数据                    │
                       └──────────────────┬───────────────────────┘
                                          │ RadarFrame
        ┌─────────────────────────────────┼─────────────────────────────┐
        │                                 │                             │
┌───────▼────────┐              ┌─────────▼────────┐          ┌─────────▼────────┐
│ fusion         │              │ pipeline         │          │ storage          │
│ 多站空间对齐    │              │ 补全缺失的一半    │          │ SQLite + .rad    │
│ 扇区拼接        │─────────────>│ CFAR / 反投影     │─────────>│ 会话/航迹/事件    │
└────────────────┘              └─────────┬────────┘          └──────────────────┘
                                          │ 完整 RadarFrame
                                ┌─────────▼────────┐
                                │ Tracker          │  关联 + alpha-beta
                                └─────────┬────────┘
                                          │ tracks
                    ┌─────────────────────┼──────────────────────┐
            ┌───────▼───────┐    ┌────────▼────────┐   ┌─────────▼────────┐
            │ Alarm Engine  │    │ UI 视图          │   │ calibration      │
            │ 去抖/滞回/冷却 │    │ PPI/A显/瀑布/RD  │   │ 标定 + 交会       │
            └───────────────┘    └─────────────────┘   └──────────────────┘
```

**单向依赖**：右边的东西不知道左边存在。UI 不认识串口，驱动不认识 Qt。
破坏这条就是架构在腐烂，改之前先想清楚。

## 二、五条数据契约

改这五个结构会影响全局，务必谨慎。

### 1. `Target`（core/model.py）
一个目标。坐标以**雷达为原点**，`x` 向右，`y` 向前，单位米。

```python
x, y        # 位置
vx, vy      # 速度，m/s
snr         # 归一化 0~1，只用于显示强弱
tid         # 航迹号，-1 表示还没建航迹
missed      # 距上次命中多少秒（注意是秒，不是帧）
threat      # 威胁等级 0~3，只有高端雷达给
cls         # 敌/友/未知，只有带 IFF 的雷达给
rcs         # 截面积，dBsm
```

`rng` / `az` / `speed` 是**属性**，由 x/y 算出来，不要单独存。

### 2. `RadarFrame`（core/model.py）
一帧数据。**所有驱动必须返回它**，不允许自定义结构。

```python
timestamp   # 用 time.monotonic()，全工程统一时间基准
scan        # (n_az, n_rng) float32 0~1，强度矩阵，可为 None
az_axis     # (n_az,) 弧度，0 在正前，顺时针为正
r_axis      # (n_rng,) 米
targets     # list[Target]
rd          # (n_doppler, n_range) 距离-多普勒图，可为 None
rd_v_axis   # 速度轴，m/s
meta        # dict，驱动私有信息（状态文本、fresh_az、scan_period…）
```

两条规矩：
- 有 `scan` 就必须给 `az_axis` 和 `r_axis`，长度要对得上
- `meta["fresh_az"] = (start, stop)` 告诉框架"这一帧只刷新了这几个方位格"，
  旋转雷达必须给，否则扫描拖尾会被当成目标

### 3. `Capabilities`（core/model.py）
能力声明。**界面显示什么全靠它**，加字段比加 `if 型号` 好一万倍。

关键字段：`source`（数据源）、`form`（形态）、`has_scan/has_targets/has_velocity/
has_range_doppler/has_iff/has_threat`、`range_min/range_max`、`az_fov`、
`scan_mode`（staring/rotating）、`views`（支持哪些视图）。

### 4. `RadarDriver`（core/driver.py）
四个必须实现的方法：`capabilities()` / `open(**kw)` / `read()` / `close()`。

`read()` 允许阻塞一小会儿（内部 poll），没数据返回 `None`。
**不要在里面 sleep 太久**，上层是轮询式的。

### 5. `Transport`（core/transport.py）
`open/read/write/close`。驱动只用这四个，不许直接 `import serial`。

## 三、补全流水线（为什么"通用"成立）

不同雷达给的东西不一样，但只可能是两种原料之一。`pipeline.normalize()` 做三件事：

```
有 scan 无 targets  →  CA-CFAR 峰值检测  →  得到 targets
有 targets 无 scan  →  高斯反投影        →  得到 scan
两者都有            →  原样透传（高端雷达）
```

于是**所有视图对任意雷达都成立**：PPI 有图可画、A 显有剖面、航迹表有目标。

CFAR 的两个关键参数（`pipeline._cfar_background`）：
- `guard` 保护单元：目标在方位上会被波束展宽，不让它进背景估计
- `train` 训练区：太大则响应慢，太小则虚警高

> 踩过的坑：早期用 3×3 邻域直接求背景，宽波束目标把自己算进背景，
> 门限被抬高，**看着有回波却报不出目标**。

## 四、融合层

`core/fusion.py` 的 `FusionEngine` 把 N 台子雷达合成一帧。对外只有 `poll()`，
返回的还是一个普通 `RadarFrame`——**所以上层完全不知道下面是 1 台还是 6 台**。

三个要点：

1. **空间对齐**：`local_to_global(x, y, spec)` 先按 `bearing` 旋转再平移。
   所有子雷达的坐标系必须一致，否则拼接处会错位。

2. **性能**：本地格 → 全局格的下标只在轴变化时算一次（`_build_lut`），
   每帧只做一次 numpy 花式赋值。6 台 19fps。

3. **两处必须做的修正**：
   - `_close_gaps()`：本地距离格比全局格粗时，散射会留空洞 → 3×3 最大值闭运算
   - 噪声**覆盖不累加**：`scan += noise` 会收敛到 `noise/(1-decay)`，底噪抬升

## 五、标定层

`core/calibration.py`。核心结论写在这里，避免后人重复踩：

**雷达只知道"目标相对我视轴偏了多少度"，这个量不含绝对信息。**
安装朝向必须由外部标定，否则"传感器角度"和"世界长什么样"是耦合的，解不出来。

流程：已知点 → `calibrate_bearings()` 求偏置 → `apply_offsets()` 写回 →
`residual_report()` 用同批点反算位置做验收。

角度统计**必须用圆均值**（`circular_mean_deg`），不能用算术平均：
`+179°` 和 `−179°` 的算术平均是 0°，真实平均是 180°。

`locate()` 是多条方位线的最小二乘交点，闭式解无迭代；
射线近乎平行时 `det≈0`，必须返回 `None` 而不是给个飞出天外的点。

## 六、扩展点清单

| 想加什么 | 改哪里 | 要不要改主程序 |
|---|---|---|
| 新雷达 | `drivers/xxx.py` + `@register` | 加一行 import |
| 新雷达（第三方） | `plugins/xxx.py` + `setup(api)` | 不用 |
| 新传输方式 | `transport.py` 加类 + `_SCHEMES` | 两处 |
| 新视图 | `ui/xxx.py` + `mainwindow` 里挂上去 | 是 |
| 新告警规则类型 | `alarm.py` 的 `_measure()` 加分支 + `PARAM_HINTS` | 两处 |
| 新告警规则实例 | 界面编辑器 或 `plugins/*.py` | 不用 |
| 新配色 | `theme.py` 的 `PALETTES` | 一处 |

规律：**越靠近"数据"的扩展越容易（插件级），越靠近"呈现"的越要改代码。**
这是正常的——视图本来就需要人设计。

## 七、线程模型

只有一个后台线程：`ReaderThread` 跑 `driver.read()` 循环，通过 Qt 信号把
`RadarFrame` 抛给主线程。

- **所有 UI 更新都在主线程**，不要在驱动里碰 Qt 对象
- 存储写入也在主线程（`Store` 内部加锁 + 批量提交，20 帧/秒不成问题）
- 插件如果有自己的线程，自己负责收尾（框架不做回收）

如果将来要把存储挪到线程，注意 SQLite 连接不能跨线程共享（当前
`check_same_thread=False` 是为了方便，挪线程时要重新设计）。

## 八、性能预算

| 环节 | 实测/估算 | 备注 |
|---|---|---|
| PPI 渲染 | ~3 ms/帧 | LUT 散射 + 两趟 3×3 膨胀 + 调色板映射 |
| 融合 6 台 | ~12 ms/帧 | 主要是散射与闭运算 |
| CFAR 检测 | ~1 ms/帧 | 积分图实现，与窗口大小无关 |
| SQLite 写入 | ~2 ms/批 | 0.4s 一次批量提交 |
| 整体 | 19–20 fps | 6 台融合、360×200 栅格 |

优化顺序：先降刷新率（20→10Hz 用户几乎无感），再降栅格，最后才考虑换渲染技术。

## 九、几个刻意的取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 矩阵存哪 | `.rad` 二进制，不进 SQLite | 20fps×180×144 一小时几十 GB BLOB，库会撑死 |
| 航迹滤波 | alpha-beta 而非卡尔曼 | 目的是"框别抖"，不是发导弹；三十行好维护 |
| 融合重叠区 | 取 max（近似） | 真实最优要做 plot-level 加权，等交会定位上线再换 |
| 单文件 exe | 不用 `--onefile` | 每次启动解 60MB 到临时目录，且 data 会撒到桌面 |
| UI 框架 | PyQt5 而非 Web | 桌面实时刷新、串口、打包成熟度 |

## 十、如果要大改

以下情况需要先改这份文档、再改代码：

- 引入新的数据形态（比如原始 ADC / IQ 采样）
- 把融合从"驱动"提到"服务"（多进程 / 多机）
- 换渲染技术（OpenGL / WebGL）
- 引入账号与权限体系
