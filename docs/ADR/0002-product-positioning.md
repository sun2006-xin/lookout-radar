# ADR-0002：产品定位——以 DIY/教学为入口，以工程留证为深度

- 状态：已采纳（2026-11-26，v1.1 补充：后续已按用户需求补齐中英双语 i18n，并将 3D 俯仰 RHI 纳入 ROADMAP 阶段 E）
- 背景：软件同时服务教学/DIY 演示与工程留证两个场景，需明确功能演进时的优先级取舍

## 两个候选

| | A. 教学 / DIY | B. 工程交付 |
|---|---|---|
| 典型用户 | 课设、毕设、STM32/树莓派玩家 | 多站组网、甲方验收 |
| 要什么 | 插上就有画面、设备一换就能用、轻 | 稳定、审计、报表、留证 |
| 代价 | 功能多、面广 | 少而深、迭代慢 |

## 决定

**A 是入口，B 是深度。**

- 入口必须是 A：一个从没用过的人解压后双击，选「模拟与演示 → 多站融合」，
  十秒内要看到会动的雷达画面。所有驱动、模拟器、连接向导都服务于这个"第一眼"。
- 深度落在 B：一旦用户留下来布站、接真机，他要的是**可靠与可追溯** ——
  SQLite 留证、统计检索、告警抑制、录像、导出。这块不出错比功能多更重要。

## 由此产生的取舍规则

1. **新设备支持优先于新图表**：加一个驱动的收益 > 加一个好看的视图。
2. **失败必须可见**：写库失败、坏帧暴涨、连接没数据，一律要在界面上亮出来，
   不许只写日志（R1 / S1 就是这么来的）。
3. **默认零配置**：默认主题、默认量程、默认端点都要能直接用，不要求用户先读文档。
4. **高危操作二次确认**：删除警戒区、转发到公网、录像覆盖，都要问一句。
5. **不加"看起来专业但没人用"的控件**：工具栏按使用频率分层，次要项进「设置」。

## 不做的

- 不追 AIS 静态/航程冗余报文、不做矢量地图编辑、不直接下发真实武器作动或违规射频功放指令
- 不做云端 / 账号体系

## 后果

- README 的一句话介绍按 A 写，特性表按 B 展开
- CI 与单元测试优先覆盖"接设备 → 出帧 → 留证"主链路
- 演示动图是 A 路线的直接产物（第一眼体验）
