## ① 可靠性 / 并发

### R1 ✅ 存储写失败曾是无声事件

`Store.flush()` 原来没有异常边界，写库失败要么冒泡被上层吞掉、要么让 pending 一直堆积。
现在：

- `write_errors` / `last_error` 计数，异常时保留 pending 以便重试，并设 5000 条上限防止内存膨胀
- **状态栏独立一栏**显示「⚠ 存储异常 N」，红色加粗；正常时显示转发包数
- 同时写 warning 日志

验证：`test_core.py` 的 20 组照常跑真实 SQLite；状态栏刷新处在离屏帧循环里走过。

### R2 ✅ UI 线程里的阻塞测试连接

`LinkDialog._test()` 原来是 `while + time.sleep(0.02)` 顶在 UI 线程 1.2 秒，且无法取消。
改成 **QTimer 20ms 轮询**：

- 按钮文字变「停止测试」，再点一次立即结束
- `closeEvent` 里收尾，不会把串口留在后台
- 界面全程可响应

### R3 ✅ 地图下载线程可取消

`MapLayer._start_fetch()` 现在先 `requestInterruption()` + `wait(300)`；
新增 `MapLayer.stop()`，关闭地图时调用。

### R4 ✅ AIS 停止后不再写表

`feed_line()` 首行加 `if not self.running: return None`。
原本 `stop()` 之后残留的 `recvfrom` 仍可能改 `_targets`。

**未发现数据竞争**：`_targets` / `_cflat` / `_trails` 都是单线程写或已有锁。
这一条保持原结论。

## ② 安全 / 健壮性

### S1 ✅ UDP 转发目标校验

新增 `is_public_target(host)`：环回 / 私网 / 链路本地 / 组播 / 受限广播 = 安全；
其余（含解析后的公网 IP、解析失败的域名）= 从严判为公网。
界面配置公网地址时弹二次确认，拒绝则回落到 `127.0.0.1` 并取消转发。

验证：`127.0.0.1 / 192.168.4.1 / 10.0.0.5 / 255.255.255.255 / 239.1.2.3` → False；
`8.8.8.8 / example.com` → True。

### S2 ✅ 瓦片缓存上限

`TileStore.prune(max_bytes=200MB)` 按 mtime 删最旧瓦片，
主窗口每 1 秒的地图刷新周期里调用。另加 `cache_bytes()` 便于查看。

验证：5×100B 缓存，`prune(250)` 删 3 个，剩 200B。

### S3 ✅ 插件警示

插件管理对话框顶部加琥珀色警示条：
「插件是任意 Python 代码，加载即在本机执行，只加载你信任的来源」。

### S4 ✅ 原判无风险（SQL 全参数化）

复查确认 `storage.py` 所有查询都用 `?` 占位，`query_events` 的动态条件也是追加占位符。

## ③ 可用性 / UX

### U1 ✅ 警戒区删除不再"删最近一个"

改成**删你点中的那个**：

- `set_alarm_zones()` 现在带 `rule_id`（5 元组）
- PPI 右键 → `_zone_at()` 做命中测试（重叠时取最小的圈）→ 高亮（琥珀实线）
  → `zoneDeleteRequested(rule_id)`
- 主窗口按 id 从 `rules.json` 精确删除，二次确认；内置规则会提示去规则表改

「最近一个」在区多了以后根本不可预测，这个改动消除了误删。

### U2 ✅ 界面内自检

帮助菜单 →「运行自检…」。核心逻辑抽到 `core/selftest.py::run_core_checks()`，
三个入口共用：`Lookout.exe --selftest`、帮助菜单、CI 的 `tools/check.py`。
结果打到事件日志，失败额外弹窗。

（顺带修了一个耦合：以前自检逻辑只存在于 `main.py`，界面想调用得 import 入口模块。）

### U3 ✅ 状态栏分段

新增 `status_link` 独立一栏（存储异常 / 转发包数），
CPA 与 fps 各占一段，不再挤在一起。CPA 危险时仍变红加粗。

### U4 ✅ 此前三项（初版已修）

## ④ 架构 / 可维护性

### A1 ✅ 主窗口拆分

`mainwindow.py` 从 **1582 行降到 1027 行**。新建 `ui/controllers.py`（641 行）：

| 控制器 | 职责 |
|---|---|
| `ConnectionController` | 连接 / 断开 / 重连 / 回放 / 端点刷新 |
| `ExportController` | 转发 / 录像 / 静音 / 导出 |
| `AlarmBarController` | 告警条 / 规则 / 警戒区增删 |

用 mixin 而非持有 owner 引用的组合，是为了让 `self.xxx` 语义原封不动 ——
拆的是"代码放哪"，不是"谁负责"，因此行为零变化。
`ReaderThread` 与主题/告警常量一并搬入，mainwindow 只留编排。

验证：离屏构造 `MainWindow`，12 个关键方法齐备、MRO 正确；
跑 7 秒真实帧循环（17.2 fps、航迹表 5 行）无 `NameError`。

### A2 ✅ Capabilities 单一同步点

新增 `RadarDriver.resolve_capabilities()`，用 `dataclasses.replace` 一次性合并
`source/form/vendor` 类属性。删掉 `_on_driver_changed` 和 `_connect` 里两处手工补三行 ——
之前漏一处就出「共视列不显示」的 bug。

### A3 / A4 ✅ 原判优点，保持

- `RadarFrame` 五字段收敛（换设备不改界面）
- 20 组测试不 mock，直接跑真实算法与真实 SQLite

## 剩余风险（不属于初版发现，如实记录）

1. **真运动边缘**：极大量程下的透镜形裁剪还需实机观感确认。
2. **瀑布图偏亮**：`max over 方位` 会把目标抹宽，正确修法是改成
   "每航迹一条距离轨迹线"，属于显示形态重设计，不是调参数。
3. **瓦片网络**：沙箱内无法访问瓦片服务器，拼图/对齐/旋转用假瓦片验证过，
   真实下载需在联网机器上确认。
4. **桌面 .lnk**：安全策略禁止 COM 实例化，改为按 MS-SHLLINK 规范手写二进制；
   结构已校验（HeaderSize 76 / LinkFlags 0xD2 / LinkInfo 114），
   但"双击能启动"这一步需要在你的桌面点一下确认（本轮不启动软件）。

## 结论

**所有审查项已闭环。** 架构本来就干净，问题集中在"边界情况的可见性"上 ——
失败被静默吞掉、配置改错没有反馈、删东西太容易。这三类现在都有明确的界面反馈或二次确认。

下一轮的重点不该是再加功能，而是**真机联调**：9 个驱动里还有 4 个没接过硬ware，
把 LD19 / LD2450 / BLE / 真实多站组网各跑一遍，比继续写界面有价值得多。
